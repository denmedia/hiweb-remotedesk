# hiWeb RemoteDesk

**Удалённый рабочий стол Windows (и Ubuntu) на планшете и смартфоне — с полноценным тачпадом, жестами
и родной клавиатурой чехла.**

Приложение написано для Samsung Galaxy Tab S9 Ultra с чехлом-клавиатурой: планшет превращается в тонкий
клиент к вашему ПК, а чехол работает как настоящий тачпад ноутбука. На смартфоне (проверено на
Samsung Galaxy S23+ / SM-S916B) тот же сеанс управляется пальцами, а для ввода текста есть экранная
клавиатура. Под капотом — собственный клиент RDP на Kotlin, без FreeRDP и сторонних библиотек протокола.

## Что умеет

### Рабочий стол без компромиссов
- **RDP с расширенной безопасностью**: TLS, NLA (CredSSP/NTLM), закрепление сертификата по SHA-256.
- **Графика двумя путями**: классические битмап-обновления (для Windows по умолчанию) и конвейер RDPEGFX —
  без него не получить картинку от GNOME Remote Desktop в Ubuntu; для Windows он включается в настройках ПК
  («Графический конвейер», пока экспериментально). В конвейере работают RemoteFX Progressive, ClearCodec и
  H.264 с аппаратным декодированием видеочипом планшета: Ubuntu шлёт его, если умеет кодировать видео
  (VA-API или NVENC), Windows — по своему усмотрению; иначе сеанс идёт без H.264.
- **Сеанс продолжается в свёрнутом приложении**: служба переднего плана не даёт Android заморозить
  соединение.
- **Поворот экрана меняет размер рабочего стола**: в книжной ориентации стол 1920 по высоте, без выхода
  из сеанса (Windows сохраняет сеанс даже при переподключении).
- **Масштаб интерфейса Windows** (100–300 %) и **глубина цвета** (16/24/32 бита) — на каждый ПК отдельно. Windows применяет масштаб только к новому сеансу: уже открытый сеанс сохраняет свой.

### Тачпад чехла как в ноутбуке
- Курсор с ускорением, левая/правая/средняя кнопка, физический щелчок.
- Прокрутка двумя пальцами в стиле macOS по вертикали и по горизонтали (дрожание пальцев гасится, явное движение по диагонали прокручивает обе оси), с **инерцией** (сила прокрутки
  и сила инерции настраиваются на каждый ПК).
- Щипок — масштаб (Ctrl + колесо).
- Свайпы тремя-четырьмя пальцами: обзор окон, рабочий стол, переключение виртуальных рабочих столов.
- Перетаскивание «лежащий палец + второй палец», как на трекпаде Mac.
- Калибровка осей — тачпад в чехле установлен боком относительно экрана.

### Перо Samsung (S Pen)
- Над экраном курсор идёт за пером, касание — щелчок, кнопка на пере — правая кнопка мыши.
- Движение пера по экрану зависит от курсора Windows под ним: над текстом («I») — выделение, у границ окон и
  разделителей — перетаскивание, в остальных местах — прокрутка по обеим осям с инерцией. Чтобы перетащить значок
  или окно за заголовок, придержите перо на месте и ведите. Форму курсора присылает HiWeb Agent (1.9.4+).
- Скорость прокрутки пером (50–200 %, 100 % — как пальцем) настраивается отдельно: в форме ПК и в настройках сеанса.
- Кнопка на пере: правая кнопка, ластик, средняя кнопка, фрагмент экрана (Win+Shift+S) или отмена (Ctrl+Z).
- В режиме «Перо Windows» программы получают настоящее перо: наведение, нажим, наклон, кнопку и ластик.
- Пока перо над экраном, касания ладонью игнорируются (можно выключить).

### Нативное касание Windows
- Вместо имитации мыши пальцы и перо передаются Windows настоящими касаниями (RDPEI): прокрутку, щипок, контекстное
  меню по долгому касанию, жесты от краёв экрана, сенсорную клавиатуру и рукописный ввод с нажимом пера ведёт сама Windows.
  Жесты приложения (три-пять пальцев, сила скролла и инерции, прокрутка пером по форме курсора) в этом режиме не работают.
- При первом подключении к ПК режим включается сам, если Windows открыла канал касаний. Переключается в форме ПК
  («Касание экрана»: Авто / Нативное / Мышь), в настройках сеанса и в меню «⋮» → «Касание». Если Windows канал не открыла,
  пальцы остаются мышью. Только Windows.
- Перо S Pen в нативном режиме настраивается отдельно (форма ПК и настройки сеанса): **Мышь** (наведение, правая кнопка, жесты
  по форме курсора), **Касание пальцем** (перо идёт обычным касанием, без наведения и нажима) или **Перо Windows** (наведение, нажим,
  кнопка, ластик; если ПК перо не принимает — мышь). Без нативного режима перо всегда как мышь.

### Жесты на самом экране
В режиме мыши три-пять пальцев переводятся в сочетания клавиш Windows или GNOME: отмена/повтор, копировать/вставить/вырезать,
Alt+Tab, «домой», переключатель приложений.

### Клавиатура и мышь
- Физическая клавиатура чехла и Bluetooth-клавиатура работают напрямую.
- **Скорость курсора Bluetooth-мыши** настраивается на каждый ПК (50–200 %); тачпад чехла
  не затрагивается.
- Служба специальных возможностей доставляет на ПК **Win, Alt+Tab и другие** сочетания, которые Android
  иначе забирает себе. Работает только пока открыт экран сеанса.
- Автоповтор клавиш как в Windows: пауза, затем частые повторы.
- **Компактная панель сеанса** (таблетка с иконками и отдельная красная «Отключиться», остальное — в меню «⋮») и
  кнопка экранной клавиатуры Windows с тремя режимами: **показана / скрыта / автоматически** (в авто-режиме клавиатура
  появляется при касании поля ввода на ПК и прячется при касании вне его) — нужен HiWeb Agent 1.9.1+; без него (и для Ubuntu)
  кнопка открывает клавиатуру Android. Если на ПК агент старее приложения, в панели сеанса появляется кнопка «Обновить агент».

### Смартфон
- **Список ПК под узкий экран**: фильтры строкой чипов, одна колонка карточек, питание — в меню «⋮».
- **Компактная панель сеанса внизу** над клавиатурой: клавиатура (показана / скрыта / автоматически), микрофон,
  камера, геолокация, Win, меню «⋮» (настройки, поворот, Ctrl+Alt+Del, Alt+Tab, агент) и красная «Отключиться».
- **Экранная клавиатура Android** работает как ввод на ПК: символы, Shift/Ctrl/Alt/Win, стрелки, Tab,
  Enter, Backspace уходят в сеанс. Win+Tab и другие сочетания — как в Windows.
- Управление — пальцами по рабочему столу (касание, долгое касание, прокрутка, щипок), как на iPad;
  захват тачпада и калибровка на телефоне не нужны и не включаются.

### Файлы, буфер и звук
- **Текст через буфер обмена** в обе стороны.
- **Файлы через буфер обмена**: скопировали файл на планшете — вставили на ПК (Ctrl+V), и наоборот;
  файлы с ПК сохраняются в `Загрузки/RemoteDesk` с индикатором прогресса.
- **Общий диск**: папка планшета видна в Windows как сетевой диск `\\tsclient\Имя`, в том числе
  «только для чтения». Диск можно подключить прямо во время сеанса.
- **Звук ПК** воспроизводится на планшете (канал rdpsnd). Опция «Сжатие звука» в настройках устройства
  включает сжатые форматы (ADPCM, G.711): поток в 2–4 раза меньше, полезно при медленной связи.
- **Микрофон планшета** доступен в Windows (канал audin, устройство записи «перенаправлено»): включается
  в настройках устройства и кнопкой «Микрофон» в меню сеанса; без разрешения Android на запись не работает.
  С опцией «Сжатие звука» микрофон тоже передаётся сжатым.
- **Камера планшета** видна программам Windows (Zoom, Skype, «Камера») как обычная веб-камера, 720p:
  включается в настройках устройства и разрешением Android на камеру; передача идёт, только когда
  программа на ПК её открыла, — как у настоящей веб-камеры, без отдельного тумблера.
- **Геолокация планшета** — программы Windows (карты, погода, браузер) получают координаты планшета как от датчика
  местоположения. Включается в настройках устройства, передачу переключает кнопка «Геолокация» в панели сеанса
  (разрешение Android на местоположение спросит при первом нажатии); в Windows должен быть включён доступ к местоположению.

### Один экран — все компьютеры
- Карточки ПК с **живым превью экрана**, поиском, фильтрами («онлайн», «оффлайн», по ОС) и сортировкой.
- **Поиск ПК в сети** одной кнопкой: скан подсети и определение ОС по баннеру SSH и ответу RDP — без
  ввода учётных данных.
- **Поделиться ПК по QR-коду**: кнопка на карточке показывает QR с настройками ПК (или отправляет его картинкой), на
  другом устройстве «Добавить по QR-коду» сканирует его камерой или читает с изображения. Пароль в код попадает только
  по явному согласию.
- **Состояние ПК по-человечески**: «онлайн», «за ПК работают», «экран заблокирован», «вход не выполнен»,
  «сон», «гибернация», «перезагружается», «выключен».
- **Пробуждение по сети (Wake-on-LAN)**: подключение к спящему ПК сначала будит его, затем ждёт порт RDP.

### Питание ПК
Три пути — какой доступен, такой и используется:
1. **HiWeb Agent** (ПК на связи по локальной сети): выключить, перезагрузить, сон, гибернация — с учётом
   реально поддерживаемых ПК режимов.
2. **SSH для Ubuntu**: команда уходит без открытия рабочего стола.
3. **Через сеанс RDP**: приложение входит, открывает штатное меню питания Windows и отключается —
   на ПК ничего не устанавливается.

### HiWeb Agent для Windows (необязательно, но именно он делает связку «планшет + ПК» целой)
- **Установка из приложения**: exe доставляется на ПК как временный диск через уже открытый сеанс
  и запускается в окне «Выполнить» — без скачивания, флешек и почты.
- **«Переключиться на Планшет» из меню в трее**: ПК сам зовёт планшет, сеанс открывается, мониторы гаснут.
- **Уведомления Windows на планшете**, пока приложение свёрнуто (с фильтрами от Phone Link и своих).
- **Сенсорная клавиатура Windows по требованию**: приложение сообщает агенту, есть ли у планшета клавиатура и какой режим
  клавиатуры выбран; агент показывает или прячет TabTip (в авто-режиме — по щелчку в поле ввода).
- **Папки ПК как диски на планшете, без трансляции экрана**: в окне «Доступ к файлам…» (меню агента в трее) владелец
  открывает одну или несколько папок и для каждой выбирает «только чтение» или «чтение и запись». На планшете они появляются
  отдельными дисками в системном приложении «Файлы» и в выборе файла любого приложения (значок папки на карточке ПК открывает
  «Файлы» сразу на диске ПК): смотреть, скачивать, загружать, переименовывать, создавать папки, удалять (в корзину Windows).
  Выключено по умолчанию; передача зашифрована, пути проверяет агент, запись в «только чтение» он не пропустит.
- **Превью ПК без сеанса**: агент раз в 15 минут присылает зашифрованный снимок экрана.
- **Защита RDP**: агент ведёт журнал подключений к ПК (кто и с какого адреса входил, неверные пароли),
  сам замечает подбор пароля (уже после 3 неудачных попыток) и вход с неизвестного адреса и предупреждает уведомлением
  в трее Windows и на планшете. Подсеть нападающего блокируется одним нажатием в уведомлении (брандмауэр Windows;
  Windows спросит подтверждение на ПК).
- **Автоблокировка** (включена по умолчанию, 5 неудачных попыток за час с одной подсети): агент сам блокирует подсеть,
  если на ПК установлен «помощник блокировки» — маленькая служба Windows, которая ставится один раз (один запрос прав
  администратора) и дальше блокирует без запросов, даже когда вас нет у ПК. Порог и переключатель — в окне «Защита
  подключений» на ПК и в приложении. Свои и знакомые адреса не блокируются.
- **Уведомления на планшет о каждой неудачной попытке входа и о каждой блокировке** — на все подключённые устройства
  (по локальной сети и из сеанса). Попытки с одной подсети обновляют одно уведомление (счётчик «до блокировки: N»).
- **Белый список**: знакомые адреса и целые подсети не проверяются и не блокируются. Адрес, с которого подключился
  планшет, агент заносит сам (адрес или всю подсеть — на выбор), остальное добавляется вручную с планшета или с ПК;
  «Это я» у угрозы заносит адрес, «Вся подсеть» — подсеть. Режим «Белый список» строже обычного: тревога на любую
  попытку входа с адреса вне списка, с первой же попытки, а не после нескольких неудач.
- **Иконка в трее**: силуэт ноутбука под тему панели задач с батарейкой планшета.
- **Окна и меню агента в стиле панели сеанса** (таблетки-кнопки, красная «Удалить»/«Заблокировать»): светлые на белом
  или тёмные — по настройке Windows «Режим приложений по умолчанию», смена темы подхватывается на лету.

## Начало работы

1. Установите APK на планшет (Android 13 и новее).
2. На ПК включите удалённый рабочий стол: «Параметры → Система → Удалённый рабочий стол»
   или скрипт из репозитория `tools/enable-rdp.ps1` (его нужно скопировать на ПК и запустить
   от имени администратора).
3. В приложении нажмите **«Поиск»** и добавьте найденный ПК — или введите адрес вручную.
4. Для сочетаний Win / Alt+Tab включите службу «RemoteDesk: передача клавиш» в специальных возможностях.
5. По желанию установите **HiWeb Agent**: кнопка «Установить агент» в меню сеанса.

Тачпад при первом запуске попросит один раз провести пальцем по осям — так приложение узнаёт, как
повёрнут тачпад в чехле.

**Обновление приложения.** Меню «⋮» на главном экране → «Проверить обновление»: приложение смотрит
последний релиз на GitHub и, если он новее, предлагает скачать APK в папку Downloads. Установить файл
нужно самостоятельно; по нажатию на уведомление о готовности открывается папка Downloads.

### Сборка

JDK нет в PATH — сначала указать:

```powershell
$env:JAVA_HOME = "D:\Program Files\Android\Android Studio\jbr"
./gradlew.bat --console=plain -q :app:testDebugUnitTest :app:assembleDebug
```

APK: `app/build/outputs/apk/debug/app-debug.apk`. Отладочная сборка ставится на планшет по беспроводному
adb: `adb install -r -t app-debug.apk`.

Агент (только C# 5):

```powershell
windows-agent\build.cmd
```

Скрипт кладёт `HiWebAgent.exe` и `version.txt` в `app/src/main/assets/agent/`. Чтобы приложение предложило
обновление агента, увеличьте `windows-agent/VERSION`, пересоберите агент, затем APK.
Проверки правил защиты RDP (адреса, подсети, обнаружение подбора пароля): `windows-agent\tests\test.cmd`.

### Протокол и порты

| Канал | Порт / транспорт | Назначение |
|---|---|---|
| RDP (Windows) | TCP 3389, TLS + NLA | сеанс, графика, ввод |
| RDP (Ubuntu) | TCP 3390 | GNOME Remote Desktop (требует RDPEGFX) |
| Статические каналы | внутри RDP | `cliprdr` буфер/файлы, `rdpdr` общий диск, `rdpsnd` звук |
| Динамические каналы | внутри RDP (drdynvc) | `HiWeb::Agent`, курсор, `RDPEDISP` смена размера стола, `AUDIO_INPUT` микрофон, `RDCamera_Device_Enumerator`/камера, `Microsoft::Windows::RDS::Location` геолокация (MS-RDPEL), `Microsoft::Windows::RDS::Input` касания и перо (RDPEI) |
| Агент ↔ планшет | TCP 47853 (можно сменить в настройках ПК), JSON + HMAC | состояние ПК, питание, превью, «switch» |
| Приглашение планшета | UDP, тот же порт, что и TCP агента | подписанная команда «Переключиться на Планшет» |
| Wake-on-LAN | UDP 9 и 7 | пробуждение спящего ПК (широковещательно) |

Раскладки PDU взяты из исходников FreeRDP; байтовые структуры — `rdp/Bytes.kt`.
Сообщения каналов режутся на фрагменты по 1600 байт.

### Формат устройства

`Device`: `id`, `name`, `host`, `port`, `os` (`WINDOWS`/`UBUNTU`), `username` (`ДОМЕН\имя`), пароль,
`certSha256` (закреплённый сертификат), `useNla`, `scalePercent`, `scrollLevel`/`inertiaLevel`,
`fileTransfer`, `microphone`, `camera`, `drive*` (общий диск), `colorDepth`, `wakeMac`.
Хранится в SharedPreferences (`devices`), пароли — только в зашифрованном виде.

### Безопасность

- Пароли — AES-GCM ключом из Android Keystore (`SecretBox`), без пароля в открытом виде на диске.
- Сертификат ПК закрепляется при первом подключении; смена сертификата отменяет подключение.
- Ключ SSH-хоста запоминается при первом входе и сверяется до отправки пароля.
- Команды по локальной сети подписываются HMAC-SHA256; снимки экрана — AES-256-CBC.
- Вход в «Переключиться на Планшет» защищён подписью, окном часов (±5 мин) и однократностью `nonce`.
- Блокировка подсетей меняет брандмауэр, поэтому идёт либо через запрос Windows о правах администратора на ПК (вручную;
  повышенная копия агента заново проверяет подсеть и не блокирует локальные адреса и диапазоны шире /16), либо через
  помощника — службу Windows из `Program Files`, установленную одним запросом UAC. Помощник слушает именованный канал,
  закрытый для всех, кроме установившей его учётной записи (и для сети), и по запросам только добавляет и убирает правила
  для публичных подсетей не шире /24 (IPv6 — /64), не больше 200 новых в час; удаляется из окна защиты или при удалении агента.

### Тесты

`app/src/test/` — JVM-тесты на протоколы и чистую логику: разбор PDU cliprdr/rdpdr/rdpsnd/audin/rdpecam/дисплей-канал,
декодер курсора, жесты тачпада и тачскрина, инерция прокрутки, детектор ОС, крипто, статусы ПК, SecureLines,
сравнение версий агента, файловый клиент и идентификаторы дисков ПК (с эталонными значениями шифрования от .NET-агента).
Агент: `windows-agent\tests\test.cmd` (правила защиты RDP и доступ к файлам). Инструментальные тесты (`connectedAndroidTest`) переустанавливают приложение
и удаляют сохранённые ПК — на рабочем планшете их не запускать.

### Ограничения

- Клиент рассчитан на Windows и Ubuntu с GNOME Remote Desktop; другие RDP-серверы не гарантируются.
- Микрофон, камера и геолокация планшета перенаправляются только в Windows: GNOME Remote Desktop эти устройства в сеанс не отдаёт.
- Камера передаёт несжатый NV12 (без H.264/MJPEG), поэтому разрешение ограничено 720p — компромисс ради
  простоты и совместимости без стороннего кодека.
- Сенсорная клавиатура Windows, уведомления и доступ к файлам без экрана требуют HiWeb Agent (для файлов — 1.11+); без него сеанс полностью работоспособен.
- Диски ПК — через `DocumentsProvider`: приложения, которым нужен обычный путь `/storage/…`, их не откроют. Не все оболочки
  показывают такие диски в главном дереве своего файлового менеджера (в выборе файла и в приложении «Файлы» Google — показывают).
  Уведомления Windows приходят на планшет, пока открыт сеанс RDP, а приложение свёрнуто. Если они не приходят,
  в меню значка агента есть «Проверить пересылку уведомлений…»: показывает тестовое уведомление и по шагам, где оно
  застряло.
- Защита RDP работает только на Windows с агентом. Уведомление об угрозе приходит на планшет, когда он в одной сети
  с ПК или в сеансе; остальное планшет получает при следующем подключении (журнал и угрозы досылаются).
  Выключенный брандмауэр Windows не применяет правил блокировки — агент предлагает включить его (при установке помощника
  и при ручной блокировке). Автоблокировка без установленного помощника подсеть не блокирует: планшет получает уведомление
  об этом (не чаще раза в час на подсеть).
- На планшете (с физической клавиатурой или чехлом-тачпадом) системная клавиатура Android в сеансе не
  показывается — ввод идёт с клавиатуры и тачпада; кнопка клавиатуры в панели сеанса открывает её вручную
  или по полю ввода на ПК (режим «автоматически»).
  Экранная клавиатура из настройки «Планшет» нужна только планшету без физической клавиатуры.
